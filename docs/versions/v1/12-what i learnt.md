# Version 1 - Learning Journey

## Introduction

Version 1 was more than just adding new features. It was a journey of understanding how to organize software, apply Object-Oriented Programming principles, and think like a software engineer.

This version helped transform my approach from writing code that works to designing code that is clean, maintainable, and extensible.

---

## What I Learned

### Core Java

- Better understanding of classes and objects.
- Improved use of constructors and object relationships.
- Applied encapsulation effectively.
- Used enums to represent fixed values.

---

### Object-Oriented Programming

- Composition
- Aggregation
- Single Responsibility Principle
- Separation of Concerns
- Layered Architecture

---

### Data Structures

- Choosing the right collection based on requirements.
- Using `HashMap` for efficient user lookup.
- Using `ArrayList` for maintaining transaction history.

---

### Software Design

- Organizing code into packages.
- Separating business logic from presentation.
- Creating reusable service classes.
- Designing repository classes.
- Returning Result Objects instead of primitive values.

---

### Problem Solving

Throughout Version 1, many parts of the application were redesigned and refactored multiple times. These iterations improved my understanding of software design and helped me recognize the importance of planning before implementation.

---

## Challenges Faced

- Deciding how to organize classes.
- Understanding object relationships.
- Designing reusable services.
- Choosing appropriate data structures.
- Keeping the Application class clean while moving business logic into services.

---

## Key Takeaways

- Writing code is only one part of software development.
- Good software is built through thoughtful design decisions.
- Clean architecture makes future development easier.
- Every refactoring improved both the project and my understanding of Java.

---

## Next Step

Version 2 will focus on further refactoring the codebase, improving the architecture, and preparing the project for Spring Boot and database integration.

The goal is not just to add new features, but to continue improving software design skills while building a more realistic banking application.
